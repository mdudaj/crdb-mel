# Access Onboarding Queue Data Contract - 2026-07-24

Status: proposed for schema implementation.

## Table

Display name: `Onboarding Requests`

Logical name: `mp_onboardingrequest`

Purpose: durable request queue for User & Access create/invite/assign onboarding. The portal creates a request row. Dataverse-triggered automation processes the row and writes the outcome back to the same record.

## Status Values

| Value | Meaning |
| --- | --- |
| `Pending` | Request was accepted by the portal and is waiting for automation. |
| `Processing` | Automation has started and owns the request. |
| `Completed` | Contact, email path, audit, and assignments were completed. |
| `Failed` | Processing stopped with a business-readable failure. |
| `Cancelled` | Administrator cancelled the request before completion. |
| `Needs Review` | Automation needs administrator action before retry or completion. |

## Request Type Values

| Value | Meaning |
| --- | --- |
| `New User` | No matching active portal contact was found during portal lookup. |
| `Existing User` | A matching portal contact or existing access profile was found. |
| `Unresolved` | Portal lookup could not determine contact state safely. |

## Permissions

Power Pages administrator web role:

- Create `mp_onboardingrequest`.
- Read request rows created through the portal.
- Read status/result fields needed by the User & Access result panel.
- Retry or cancel only through approved fields/actions when implemented.

Ordinary data collector role:

- No create, read, update, or delete permission on `mp_onboardingrequest`.

Dataverse automation owner/service account:

- Read and update `mp_onboardingrequest`.
- Create/read/update contacts through approved connection reference.
- Create/read invitations or use the native Power Pages invitation path.
- Create form assignments and access audit logs.

## Security Rules

- Do not store bearer tokens, anti-forgery tokens, client secrets, passwords, or credential-bearing URLs.
- Invitation codes may be stored only for the approved admin-only manual fallback path. Treat them as single-use onboarding material, pair them with an expiry date, and expose them only to Platform Administrators.
- Store only sanitized errors.
- Treat email as personal data; expose request rows only to authorized administrators.
- Do not create assignments unless the request row and audit write have succeeded.
- Use `mp_requestkey` to prevent duplicate processing.
